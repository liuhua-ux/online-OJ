# 实验2：需求分析 —— 软件需求规格说明书（SRS）

## 1. 引言

**1.1 编写目的**
本文档定义在线判题系统的功能需求与非功能需求，作为后续概要设计、详细设计、编码实现与测试验收的统一依据。预期读者：指导教师、项目开发人员、测试人员。

**1.2 项目范围**
系统面向编程教学与自主训练场景，提供题目管理、代码在线提交、自动编译运行与判定、判题结果反馈、排行榜等功能，采用 B/S 架构。本项目支持 C++ 单语言判题。

**1.3 术语定义与缩写**

| 术语 | 说明 |
|---|---|
| OJ | Online Judge，在线判题系统 |
| 判题器 Judge | 编译并运行用户代码、比对输出并给出结果的后端模块 |
| 测试用例 | 针对每题预设的"标准输入 + 标准输出" |
| AC / WA / TLE / MLE / RE / CE / SE | 判题状态码：通过 / 答案错误 / 超时 / 超内存 / 运行错误 / 编译错误 / 系统错误 |

**1.4 参考资料**
1. Roger S. Pressman《Software Engineering: A Practitioner's Approach》第 9 版
2. IEEE 830-1998《软件需求规格说明书推荐标准》
3. 《软件工程实验》课程实验指导书

## 2. 总体描述

**2.1 产品前景**
本系统为独立部署的 Web 应用，通过 HTTP 与浏览器交互；后端与 MySQL（数据持久化）、Redis（排行榜）协作。无外部系统依赖，可单机或部署于 Linux 服务器。

**2.2 产品功能概述**
系统核心能力：用户注册登录、浏览题目、在线提交代码、自动判题并反馈结果、查询历史提交、排行榜；管理员维护题目与测试用例。

**2.3 用户特征**
- **学生**（普通用户）：具备 C++ 编程能力，通过浏览器使用系统提交代码、查看结果；
- **管理员**：负责出题、维护测试用例与用户管理，需后台权限。

**2.4 约束**
- 开发约束：判题层为 C++（C++11/17）；一期 Web 层为 Python 3.12 + Flask；二期 Web 层改为 C++ socket + epoll + 线程池自研服务端；全程运行于 Linux 环境，使用 MySQL、Redis；
- 运行约束：服务端运行于 Linux，需具备 g++ 编译器。

**2.5 假设与依赖**
- 假设用户仅提交 C++ 语言代码；
- 假设服务端已安装 g++ 并能执行编译；
- 判题正确性依赖每道题测试用例的准确性。

## 3. 具体需求

**3.1 功能需求**（按模块，P=优先级）

| 编号 | 需求描述 | 优先级 |
|---|---|---|
| FR-01 | 用户注册 / 登录，区分学生与管理员 | 高 |
| FR-02 | 查看 / 修改个人信息 | 低 |
| FR-03 | 学生浏览题目列表、查看题目详情（题面、输入输出说明） | 高 |
| FR-04 | 管理员新增 / 编辑 / 删除题目 | 高 |
| FR-05 | 管理员维护每题测试用例 | 高 |
| FR-06 | 学生提交 C++ 代码 | 高 |
| FR-07 | 系统自动编译，编译失败返回 CE | 高 |
| FR-08 | 运行用户程序、喂入测试用例并比对输出 | 高 |
| FR-09 | 限制运行时间 / 内存，超限返回 TLE / MLE | 高 |
| FR-10 | 返回判定结果并持久化提交记录 | 高 |
| FR-11 | 支持并发提交，判题异步排队执行 | 高 |
| FR-12 | 按通过题数 / 总分展示排行榜 | 中 |

**3.2 外部接口需求**
- **用户接口**：Web 页面（题目列表页、题目详情页、代码提交框、判题结果页、排行榜页）；
- **软件接口**：后端 ↔ MySQL（数据持久化）、后端 ↔ Redis（排行榜缓存）、后端 ↔ g++（编译用户代码）；
- **通信接口**：浏览器 ↔ 后端采用 HTTP 协议。

**3.3 性能需求**
- 单次判题响应时间（不含排队）≤ 3 秒；
- 支持 50 个并发提交排队判题；
- 排行榜查询响应时间 ≤ 1 秒。

> 取值依据：单次判题耗时 ≈ 编译（约 0.5 秒，只做一次，全部测试点复用）+ 最慢单测试点运行（限时 2 秒）+ 输出比对（约 0.1 秒）≈ 2.6 秒，故取 3 秒并留有余量；M 取 50，由判题线程池（8~16 线程）与有界队列支撑，高于 FR-11 的验证场景（同时 10 份提交）并留有 5 倍余量。

**3.4 逻辑数据库需求**
实体：用户、题目、测试用例、提交记录。关系：用户 1-N 提交记录；题目 1-N 测试用例；提交记录 N-1 题目、N-1 用户。（字段级设计在详细设计阶段细化）

**3.5 设计约束**
- 遵循 C++11/17 标准；
- 分层设计：Web 服务层与判题层（Judge）解耦。判题层是独立可执行程序，只通过**命令行参数 + 退出码**与 Web 层交互，因此 Web 层一期用 Flask、二期换 C++ epoll 自研服务端，**判题层完全不受影响**——这正是分层的价值所在。

**3.6 软件系统属性**
- **可靠性**：判题结果准确、无误判、不丢提交；
- **可用性**：界面简洁，操作直观；
- **安全性**：隔离运行用户代码，防恶意代码破坏服务端；口令加密存储；权限控制；
- **可维护性**：判题器独立于 Web 层，模块化、代码规范。

## 4. 需求建模（Pressman 第 9 版：场景化建模）

**4.1 用例描述**

**用例 1：提交代码并查看判题结果**
- 参与者：学生
- 前置条件：已登录
- 主流程：① 浏览题目列表 → ② 打开题目详情 → ③ 粘贴代码 → ④ 提交 → ⑤ 系统判题 → ⑥ 查看判定结果与历史记录
- 后置条件：提交记录已持久化，结果可查

**用例 2：管理员发布题目**
- 参与者：管理员
- 前置条件：已登录且具备管理员权限
- 主流程：① 新建题目 → ② 填写题面与输入输出说明 → ③ 添加测试用例 → ④ 发布
- 后置条件：题目可被学生查看并提交

> 说明：类建模（类图/CRC）、行为建模（状态图/时序图）将在概要设计与详细设计阶段补充，本阶段完成场景化建模。
