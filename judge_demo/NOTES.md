# 判题器笔记（设计与进展）

> 记录核心设计决策与实测结论，可直接用作实验报告素材。

## 当前能力

```
./judge <源文件> <数据目录>
```

五个判定全通：CE / AC / WA / TLE / RE，支持多测试点。

```
$ ./judge test.cpp testdata
compile ok
Test 1
run done
AC
Test 2
run done
AC
Test 3
run done
AC
all 3 test passed
```

退出码对照表：

| 情况 | 退出码 | 说明 |
| --- | --- | --- |
| 全部测试点通过 | 0 | |
| 某个测试点 WA / TLE / RE | 1 | 立刻停止，不再跑后面的测试点 |
| 编译失败（CE） | 1 | |
| 数据目录里没有数据 | 1 | 一组都没测，不算通过 |

## 整体结构

```
编译一次 ──→ 运行 N 次（N 由数据文件决定）──→ 逐组比对
fork + exec g++        fork + exec ./test
pipe + dup2(→2)        open + dup2(→0, 1)
读报错判 CE            判 TLE / RE / AC / WA
```

## 关键设计决策

### 1. 抓 g++ 报错（pipe + dup2）

- 子进程：close(fd[0]) → dup2(fd[1], 2) → close(fd[1]) → exec g++
- 父进程：先 close(fd[1])，再 read 到 EOF
- **父进程必须先 close(fd[1])**：不关的话 read 永远等不到 EOF，程序卡死（已实测）
- **read 必须写在 waitpid 之前**：否则报错超过管道容量（约 64KB）时双向死锁
- read 会"短读"，所以要 while 循环；缓冲区留一格给结束符，用 sizeof(buf) - 1

### 2. 喂输入 / 收输出（open + dup2）

- 子进程：open 输入（只读）与输出（写入 + 创建 + 清空），再 dup2 到 0 号和 1 号
- 用文件而不用管道：避免 64KB 死锁；天然对接比对逻辑；调试时可直接 cat output.txt

### 3. 超时（alarm + 信号）

- alarm 只有一处位置正确：**子进程里、exec 之前**
- fork **不继承**闹钟（实测：父进程 alarm(2) 到点被杀，子进程活满 5 秒）
- exec **保留**闹钟（实测：exec 成 sleep(10) 的程序，1.003 秒被 SIGALRM 杀死）
- 每组数据都有独立的 2 秒超时：每轮 fork 出来的子进程都是全新的，闹钟自然重新计时

### 4. 判定"被信号杀死"

- WIFEXITED 为真 → 正常退出，用 WEXITSTATUS 取退出码
- WIFSIGNALED 为真 → 被信号杀死，用 WTERMSIG 取信号号
- SIGALRM(14) → TLE；SIGSEGV(11) → RE
- 注意：WIFEXITED 为假时，WEXITSTATUS 取出的值毫无意义

### 5. 比对

- 逐行读，每行末尾补换行再拼接
- **不能丢行边界**：否则输出 "3\n0" 与答案 "30" 会被判成相等，误判 AC
- 对判题器来说，"误判 AC" 远比 "误判 WA" 严重（错的被当成对的，没人会发现）

### 6. 多测试点：怎么知道一共有几组（新增）

- 文件名按规则拼出来：`目录 + "/" + to_string(i) + ".in"`、`.ans`
  - i 从 **1** 开始 —— 数据文件叫 `1.in`，不叫 `0.in`（差一错误）
  - `open()` 只认 `char*`，`std::string` 要 `.c_str()` 转过去
- 循环写成 `for (int i = 1; ; i++)`：中间**留空** = 条件恒真 = 永不主动停，只能靠 `break` 出来
- 停止信号 = **探路石**：

```cpp
ifstream check(ans_path);
if (!check.is_open()) break;
```

- **判题器不该知道有几组数据**，只该"一组一组往下走，走到没有为止"——出题人加一组数据，不用改代码
- **探路必须在父进程做、在 fork 之前**：
  - 需要"知道没有下一组了"的是循环，而循环在父进程里，`break` 也只能在父进程写
  - 若交给子进程 `open` 失败后 `return 1` 报信 → 与用户程序自己的 `return 1` 撞车，退出码分不清
  - 且此时 `output.txt` 已被清空、报错已打到终端，副作用无法挽回
- `cout << "Test " << i` 必须放在探路**之后**，否则会多印一组空头支票（实测踩过：印了 `Test 4` 却什么都没跑）
  - 与"read 必须在 waitpid 之前"同类：**语句顺序本身就是逻辑**

### 7. 结论靠退出码（新增）

- 判题器对整个系统的唯一输出是**退出码**：0 = 通过，非 0 = 不通过
- 屏幕上打印的 AC/WA 是给**人**看的，退出码是给**程序**看的（将来 Web 后台只读退出码）
- WA 时用 `return 1` 而**不是 `break`**：`break` 只跳出循环，程序继续往下走，退出码仍是 0 —— 失败信息就丢了
- 空数据保护：`int passed` 计数器（**必须声明在 for 外面**），循环后 `if (passed == 0) return 1`
- **实测踩过的三个"假通过"**，都是"编译不报错、程序不崩、安静地说谎"：
  1. 循环里两轮读的还是同一个文件 → 假 AC（把 2.ans 改成 999 仍报 AC 才暴露）
  2. WA 却没 `return 1` → 屏幕印 WA，**退出码却是 0**
  3. 数据目录空 → 打印正常结束，**退出码 0**
